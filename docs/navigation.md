# Navigation and local links

Crystal Kit uses semantic hash routes so links work on static hosts, in a subdirectory, and with the prepared offline application. The path after `#` identifies a page, selected record, settings section, or modal action. Record links retain exact identities instead of using names as unique keys.

The app opens at the Build library without selecting a Build. The menu starts with Builds, Characters, and Reference, followed by a Tracking group containing Inventory and Progress. The expanded sidebar lists Class seals, Travel & unlocks, and Quintar breeding as nested links under Progress, highlighting the selected page. Collapsing the sidebar hides these subitems; the Progress pages also provide their own navigation tabs. Mobile navigation preserves the main destination order with a divider before the tracking destinations. Explicit page and record links still open their requested destinations. Build library, team scenarios, comparison views, character views, and settings sections have separate routes. Inventory observations, character captures and learning records, Build creation and editing, progress edits, reference overrides, and Game Setup collection also have their own addresses.

Progress pages use `#/progress/seals`, `#/progress/unlocks`, and `#/progress/quintar`. The `#/progress` root opens the first page in the shared Progress navigation order and replaces the address with that page's explicit path. The Progress menu destination follows the same order. Progress record edit addresses remain `#/progress/<record-id>/edit`.

For example, `#/inventory/new` opens the inventory form, `#/builds/teams` opens team scenarios, and `#/settings/game-setup` opens Game Setup settings. A character's Member screen uses `#/characters/<character-id>/current`, and Learn uses `#/characters/<character-id>/knowledge`. Earlier class and spell links remain supported; `#/characters/<character-id>/magic` opens Learn with Monster Magic selected. Snapshot inspection uses `#/characters/<character-id>/history/snapshots/<snapshot-id>`, and comparison uses `#/characters/<character-id>/history/compare/<snapshot-a-id>/<snapshot-b-id>`. Each ID must belong to the selected character; missing snapshots show recovery controls without substituting the current snapshot. A catalog definition uses `#/reference/catalog/<catalog-id>/revisions/<revision-id>/entities/<entity-id>`, preserving the source revision even when names are duplicated.

In-game readiness is an optional collapsed section on saved builds. Its Record as current action requires explicit confirmation that the build was applied in game; saving a build alone never changes tracked state.

The build sheet opens directly at `#/builds/library/new` on desktop and mobile, and saves its initial checkpoint together with the build. Build fields are editable search inputs with anchored selection lists; they do not create free-text definitions. Their picker routes preserve search text through Back and Forward. Existing build and checkpoint links open the inline sheet.

Definition dropdowns and their create/edit dialogs extend the parent route. Universal search has an address too. Back and Forward traverse these layers while keeping the parent form available. A picker route opens a compact dropdown anchored to its field without making the form inert or blurring it. Create and edit actions open centered modal dialogs; returning from an editor restores the dropdown search. Cancel or the close button returns to the parent view; a directly opened dialog has a safe parent destination even without an earlier app history entry.

URLs describe navigation, not a backup of unsaved form fields. Refresh can reopen the same form or picker, but unsubmitted input is not a durable saved record. Save the form before relying on a bookmark to preserve its contents. Navigation guards keep protected Build, Game Setup, and definition drafts open until they are saved or explicitly discarded. Universal search keeps an underlying form open until it is finished or closed before navigating to a result.

Personal record links depend on the active playthrough and browser storage at the same origin. A copied link does not transfer the referenced data to another browser or device. Import a native backup and select the relevant playthrough before opening its record links. A missing record or unavailable catalog revision produces a recovery message instead of silently opening a different record.

The top Playthrough and Game Setup dropdowns remain available for both buildcrafting and tracking. A Playthrough is one tracked save lineage; Builds and Game Setups are shared across Playthroughs. The Scenario dropdown appears on tracking pages, Characters, and team views; Build editing and Reference omit it. These choices persist in browser storage. Their search and open state are temporary and do not add URL history entries. A Playthrough switch returns to the current destination's list, avoiding reuse of another Playthrough's record address. Selecting a scenario while viewing teams opens that team's address. Context changes check open drafts even when they leave the route unchanged. Scenario selection and Game Setup selection are independent; a scenario's dropdown entry shows its pinned Game Setup and identifies differences from the current Game Setup.

Import previews depend on the file selected in that browser session. Their URLs cannot restore the file bytes after refresh; reopen the local file to review the preview again. Visiting any route does not approve an import or perform a saved-data mutation.

Reference and inventory filter parameters remain in the address where needed. Source filters display readable labels while retaining the exact source values for filtering and provenance. The older encoded search-target and reference-selection links are accepted and converted to semantic paths.

A slot action in the recorded character sheet opens the capture route with its definition-picker descendant. The picker focuses search on opening and returns focus to its field on closing. A changed snapshot form blocks outside dismissal, Escape, and navigation away until saved or explicitly cancelled, and warns before browser refresh. After a storage failure, closing the form leaves the application recovery draft available for Retry save or backup export.
