# Playthrough mods

Open **Data & settings > Saved setups > Edit setup > Mods** to choose **Enabled**, **Disabled**, or **Unknown** for each mod in the fixed Nintendo Switch list. Mods are grouped under **Mod Pack 1: Quality Fun** and **Mod Pack 2: New Challenges**. A single choice moves the mod between enabled and disabled without allowing both states; **Unknown** clears only that mod's setting. Installing a pack does not establish which included mods are enabled in a save. Saving creates an immutable Game Setup revision. To use it for a tracked game, open **Playthrough**, choose the revision under **Game Setup to apply**, and choose **Apply**. Saving alone preserves the Playthrough's selected rules.

The list displays **Moonlight Project** and retains **Learnable Innate Skill**. Existing backups retain the earlier Moonlight Project setting key so upgrades preserve the recorded choice. Nintendo's publisher listings for [Mod Pack 1](https://www.nintendo.com/us/store/products/mod-pack-1-quality-fun-70050000048696-switch/) and [Mod Pack 2](https://www.nintendo.com/us/store/products/mod-pack-2-new-challenges-70050000051088-switch/) use **Learnable Innate Skills** and **Moonlight Project Custom Classes** respectively. Display names do not establish mechanics or definition identities.

Case and extra whitespace do not change a recorded name's identity. Imported names outside the Switch list are shown separately and retained, including when applying the confirmed setup. Unedited knowledge stays intact. A choice resolves only that mod across imported alternatives; other disagreements remain conflicting. Revised claims are manual choices, while their original source attribution remains in the previous Game Setup revision.

**Mod sources & Nintendo preset > Apply Nintendo mod preset** applies the named mod choices shown alongside the preset. Review the choices against your save before applying them. The preset preserves platform, game version, PP rules, equipment slots, other named mods, and imported layers. The sample playthrough leaves mod settings unknown and does not apply this setup automatically.

## Definition visibility

The default Reference includes vanilla definitions and the known contents of both Nintendo Switch mod packs. Reference membership is separate from a Playthrough's enabled-mod settings. Other bundled mod files stay outside Reference until explicitly added. Imported reference catalogs and saved mod revisions are included unless removed with the Reference toggle; the standing Reference uses the latest saved source revision while older exact links and Game Setup pins remain available.

Reference, universal search, build and character pickers, and screenshot class choices retain definitions when their source mod is disabled, unknown, or conflicting. Vanilla and confirmed enabled choices appear first; other mod choices appear at the bottom with their state, and picker results use gray artwork and text. Explicitly removing a catalog from Reference excludes its entries from Reference lists and universal definition search; planning pickers retain their archived definitions and use the selected Game Setup. The built-in associations cover Equipment Expansion items, Doge Shield, Bloodmage, Tempest, Forcemage, Barbarian, the confirmed Barbarian and Tempest skills, and the separately named Mod Pack 2 bosses. These associations use exact source identities from the Equipment Expansion sheet, Nintendo publisher descriptions, and in-game class confirmation. Personal overrides inherit their source association; unrelated same-name imports and personal definitions do not.

A known source mod with an unknown or conflicting setting stays visible with that state beside the entry. Entries whose source-mod association is not established also stay visible. Moonlight Project 2.2 supplies Freelancer, Brawler, the other exported classes, and their supported definitions in the default catalog. Their source association is known, while whether the player enabled the mod depends on the recorded Game Setup. Brawler and its class skills are associated with Moonlight Project; the Monk's base-game Brawler passive is a separate definition. This is partial applicability coverage: the catalog does not establish every mod's added abilities, equipment, trainers, or tree changes. Enabling a mod does not manufacture its missing definitions or verify the catalog's platform and game-version parity. Mods that change PP costs, equipment permissions, or other mechanics are recorded as configuration; their effects are not inferred from their names.

Build selectors keep named mod definitions visible and selectable when their mod is disabled, unknown, or conflicting in the Build's pinned Game Setup. Those choices appear at the bottom in gray with an explanation. Confirmed enabled and base-game choices appear normally. Selecting a definition does not enable its mod or change the Game Setup.

Recorded inventory, character learning, snapshots, and plans are retained when a mod is disabled. Exact definition links still open, and a picker retains its current exact selection with its mod state. The current member sheet shows saved mod settings under **Observation details**; historical sheets show **Recorded mods**. Each uses the snapshot's pinned Game Setup revision and labels its recorded selections against that configuration. **Equipment Expansion mod: enabled status not recorded**, for example, means the snapshot does not record whether that mod was enabled in the game. Expand a character sheet's mod label for an explanation and a link to **Playthrough game settings**. These labels describe recorded mod settings and do not validate slot compatibility. Changing the current Game Setup does not reinterpret the earlier sheet. Capture a new snapshot to record the new context.

Supported numeric modifiers, class growth, and imported calculation constants use the selection's Game Setup, including a Build or character snapshot's pinned revision. Imported layer settings apply only when that exact layer is enabled. A selected definition from a disabled, unknown, or conflicting mod remains saved and readable, but its effects are not applied and the affected loadout totals stay unresolved with an explanation. Creating or browsing a catalog entry does not enable it. Names and arbitrary imported formulas do not supply executable calculation rules.

## Imported mod files

Open **Mods** from the sidebar to browse bundled sources and saved revisions. **Edit mod JSON** opens the latest saved JSON or the full bundled original in the [editor workspace](mod-inspector.md). **Import updated version** adds another revision with the same project ID; a different project is rejected before saving. **Import mod** accepts a separate project. Original bundled copies and earlier saved revisions remain available under **Versions & JSON source**. Saving or importing does not enable a mod or change pinned Game Setups, builds, or observations.

Bundled cards show the supported definitions available in their JSON before that source has been loaded. **View catalog entries** opens a temporary Reference page searching only that mod's catalog and associated observations. Only the selected source is loaded in memory; browsing does not import source bytes, save catalog records, or change Game Setups. Search and detail links retain the temporary scope, including after a reload. Clearing search filters keeps the chosen catalog, and **Return to Reference** restores the standing library's search. Temporary searches do not replace the standing Reference search history. If an imported update exists, browsing uses that saved version without replacing it with the bundled original. Leaving releases the temporary decoded catalog. Mods without supported definitions can still be opened in the JSON editor; other game effects remain unmodeled.

**Add to Reference** and **Remove from Reference** form a reversible toggle on mod cards and temporary catalog pages, including built-in and source-less mods with catalog entries. Adding an unsaved bundled source imports its supported definitions and exact bytes into the local archive. Removing a catalog hides its associated entries from the standing Reference and universal definition search while preserving the source archive, saved builds, observations, and Game Setup pins. Re-adding an archived catalog restores its entries without importing another copy. **View catalog entries** remains available for temporary browsing after removal. Membership persists across reloads, backups, and undo. Saving or importing a mod preserves an existing exclusion; a new mod is included by default. These actions do not enable a mod for planning. Catalog details are read-only. The selected mod's **Add catalog entry** action remains available for manually recording gaps without a JSON source.

[Crystal Project's Steam Workshop](https://steamcommunity.com/workshop/browse/?appid=1637730) is the source for published mods and updates. CryKit provides a versioned local library. The Mods page links to Workshop and to individual listings when the source declares a valid Workshop ID. Missing IDs and removed listings do not establish a replacement source or platform equivalence.

The editor decodes identifiers, edits mod JSON, and saves an applied draft directly into CryKit. Workspace originals and drafts have separate downloads; saved library revisions and their source files are included in planner backups. Full project JSON includes fields beyond the planner's supported records and settings. Custom artwork files are separate from the JSON.

Open **Mods** within Game Setup to configure exact Crystal Edit source revisions separately from the starter list of named Switch mods. Enable the chosen layers, arrange their planner priority, and review bundled replacement links before saving. Later enabled records with the same native family and ID replace earlier complete records; names do not establish links to bundled definitions. The effective definitions drive planning without changing older saved configurations. See [Configuring imported mod layers](crystal-edit.md#configuring-imported-mod-layers) for version selection, precedence, source references, unresolved targets, and supported rules.

## Mods without source files

The searchable Mods list includes bundled projects, imports, Switch preset names, names recorded in Game Setups, and source names associated with catalog or personal definitions. Cards without a source file say **Mod JSON unavailable**. Every card offers **View catalog entries** and **Add catalog entry**. The catalog link shows entries associated with that card; the add action prefills the chosen mod while other facts remain unknown. Use **Report a data issue** on an existing entry for source errors; its catalog record cannot be cloned or edited. A JSON file or active Workshop listing is optional, including for mods removed from Workshop.

Record only the values you can establish in-game. Missing facts, source versions, and platform applicability can remain unknown. Personal observations retain their own revisions. An entry added from a project card records that project's identity; existing name-only records remain readable. Curated bundled catalog names share a card with their reviewed project source, while unrelated imported projects keep separate cards even when their names match. These presentation groups do not establish artwork bindings or replacement targets. Add a custom mod name in Game Setup to record a mod outside the presets.

## Backup and recovery

Native backups preserve enabled and disabled lists with each Game Setup revision, including unknown and conflicting imported claims. Backups without a disabled list remain readable and keep those settings unknown. Older application builds that do not support the optional disabled list cannot restore backups containing it. Restoring contradictory definite enabled and disabled lists fails validation before changing the stored planner data.

Reference exclusions use the optional, versioned `referenceLibrary` settings field. Backups without that field retain the default membership behavior. Removed mod identities remain recorded even if their source is unavailable. Older application builds without this field cannot import a backup containing it; unknown settings versions fail validation before changing planner data.

Mod settings and filtering work locally without game-data requests. Existing transaction rollback, retry, undo, and offline backup behavior applies to Game Setup saves. A source association controls list ordering and calculation applicability; it never deletes a personal record or marks an ability learned.
