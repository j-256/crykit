This finite matrix maps the approved account requirements to existing producer proofs and final composed journeys. A file listed here identifies required coverage, not a passing execution claim. The execution receipt below distinguishes source-level, local runtime and hosted evidence.

Guest and account suites remain separate. Guest editing does not require a sign-in or API. Private account payloads are encrypted before durable account storage or upload; the server never decrypts them. Original bytes, exact historical pins, unknown values, invalid drafts, unsupported saves, unresolved conflicts and guest databases remain protected. Current selections and device preferences stay local.

## Final composed journeys

- Complete workspace: two independent browser contexts use the real local Worker and private storage, restore a complete synthetic workspace, publish it, reopen it on the second device, compare original bytes and historical content, preserve exact published file history, and retain local-only pending recovery content in the owner backup after reopening. Legacy native account selection migrates additively; an offline edit survives restart before its queued projection is mapped.
- Failure recovery: retained source-only Build import keeps its full owned unsaved input, applies matching definitions, saves a fresh checkpoint only on explicit Save, and retains the original checkpoint. Wrong-source and write-failure assertions remain. Separate existing draft/save conflict and interrupted-upload journeys preserve exact branches and command identity.
- Privacy and lifecycle: anonymous and administrative artifacts exclude private sentinel content; distinct account sessions and keys remain aligned through actual two-tab responses, persistent browser restart and navigation. A saved selection is never account authority.
- Local saving: compare the same Build notes, progress tile, invalid Editor draft, valid Editor Apply and Save inventory changes in small and larger prepared guest/account workspaces, including repeated edits and an active mapper. Measure actual durable and usable completion, transactions, rows, payload IO, codecs and encryption. Build notes capture their endpoint inside the browser after the acknowledged revision accepts the next trusted keystroke and retains its exact text and focus through a paint opportunity. Driver result transport follows that endpoint; missing, synthetic or late input cannot pass the unchanged one-second ceiling. One-time migration/import/restore preparation and cloud publication are separate. Main-thread counters do not measure Worker work or physical disk allocation. Active-mapper timing and the final complete history/originals oracle use named steps in one serial journey in the same live browser context; total journey duration and each foreground save measurement are reported separately.
- Resource qualification: measure actual eventual publication drain and representative request/event volume. No stronger throughput deadline follows from an exploratory timeout. Local emulation does not establish hosted CPU, D1, R2, retention or billing guarantees.

## Required commands

`npm run test:e2e` runs the static guest workflows. `npm run test:e2e:accounts:acceptance` builds the account proof bundle and runs the finite final journeys in [the immutable HTTPS configuration](../playwright.acceptance.config.ts). Run `npm run build:assets` first for a standalone invocation. Each acceptance attempt copies immutable built assets and modules once. Each functional worker owns an ephemeral HTTPS origin, fresh synthetic keys and independent Worker/D1/R2, origin overrides, response gates, fault queues, counters and captured reserved-domain email. Independent tests retain fresh browser contexts; explicit serial journeys keep their original context, keys and backend across checkpoints. Workers await owned runtime disposal, and the copied inputs remain available for diagnosis. The backend-isolation journey changes one runtime while verifying the other retains its independent behavior. The browser process accepts its synthetic certificate; this proves neither public-CA trust nor hosted provider readiness. `npm run test:e2e:accounts` remains the separate development suite. `npm run verify` includes static guest and immutable account acceptance plus deterministic Worker/API, unit, DOM, persistence, source/privacy and built-asset checks. Inspect `wt-queue verification-status --json` before the coordinated full run. No queue, PR, merge, deployment or cleanup is implied by local verification.
