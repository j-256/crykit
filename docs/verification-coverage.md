# Verification coverage

Coverage is organized around observable guarantees and distinct implementation boundaries. A test count is not an acceptance criterion. The complete required local gate includes every selected journey and deterministic check; optional or deferred work cannot substitute for a required proof.

| Boundary | Required proof | Consolidation |
| --- | --- | --- |
| Account credentials, cookies, keys, locks, restarts and privacy | Cross-browser [access](../e2e/accounts/access.spec.ts), [lifecycle](../e2e/accounts/lifecycle.spec.ts), [privacy](../e2e/accounts/privacy-boundaries.spec.ts), backend-isolation and administrative cases | Retain native browser behavior on Chromium, Firefox and WebKit |
| Complete restore, offline continuation and eventual publication | Cross-browser [complete-workspace](../e2e/accounts/complete-workspace.spec.ts) journey with a physically disconnected listener, restart, reconnect and exact second-device originals/history | The same composed journey owns native storage recovery on Firefox and WebKit |
| Delayed uploads, queued tile edits and sync status | Chromium [status-recovery](../e2e/accounts/status-recovery.spec.ts), guest queued-tile journeys and the save-performance producer | Keep delayed uploads, rapid tile edits and physical offline reload on every engine; avoid repeating the final projection drain and storage setup on Firefox and WebKit, whose completion is checked by complete-workspace |
| Storage inspection, account backup and local device-copy removal | Shared [storage assertions](../e2e/accounts/storage-recovery.ts) after Chromium status recovery or Firefox/WebKit complete-workspace | The assertions are identical; only their already-prepared account changes |
| Encrypted C/D authentication, cancellation, ownership, cleanup and transaction rollback | Real encrypted persistence matrices using [inactive-account fixtures](../src/persistence/account-inactive-test-helpers.ts) | Use compact nonempty historical metadata for fault permutations rather than repeating the payload-size cross-product |
| Segmented historical metadata and exact original bytes | Explicit segmented fixtures in [C/D transfer and legacy admission](../src/persistence/workspace-graph.test.ts) and installed [local/pull selection](../src/persistence/account-selection.test.ts) | Keep real multi-page transfer, independently borrowed streams, reopens and exact metadata/original comparisons |
| Native journal export retention boundary | Real stored [journal export](../src/persistence/guest-planner.test.ts) with newest-checkpoint selection, draft composition, import preview and unchanged-row assertions | Export performs the first full admission; the unchanged journal is admitted again after reopening, without another setup-only load |
| Foreground saves under mapper overlap | [Local-save performance](../e2e/local-save-performance.spec.ts), including first and repeated saves, small/large guest/account workspaces and actual profile-owned mapping | Report each sequence as one journey with named prepare/save/final steps; retain every attempted save, a unique complete receipt per checkpoint, the one-second ceiling and complete final originals/history checks |
| Guest workflows and responsive behavior | All configured desktop scenarios and selected mobile scenarios in [guest configuration](../playwright.config.ts) | Guest selection is unchanged by the account recovery consolidation |
| Repeated synthetic library preparation | Real UI import in the [library fixture](../e2e/mod-library-fixtures.ts); import, upgrade, offline and exact-source assertions remain in their owning journeys | Prepare the same synthetic library once per worker inside the run, then give every test a fresh native IndexedDB copy; historical upgrade starts with empty storage and imports through the UI |

Compact encrypted fixtures retain exact nonempty history, inert unknown text, original-byte comparisons, real encryption and real transactional storage. Dedicated segmented fixtures retain the larger payload boundary. This removes the size-by-fault-phase cross-product; it does not replace encrypted/native behavior with mocks or remove fault phases.

No product, cryptographic or persisted-data contract follows from test scheduling or consolidation. Changes to a promised behavior still require a product decision. A proposed consolidation must identify the retained proof and state any removed combination before changing the required matrix.
