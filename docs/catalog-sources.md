# Built-in catalog sources

Crystal Kit ships a static, revisioned reference catalog so a blank Playthrough can search and inspect Crystal Project definitions without importing a file or making a runtime network request. Catalog definitions remain separate from inventory, character learning, party progress, and other personal observations. Finding an entry never establishes that the player owns, learned, unlocked, or can use it.

## Catalog certainty and identities

`catalog-v1` is the bundled baseline. It combines fingerprinted Crystal Project 1.6.9.0 records with Moonlight Project 2.2, Equipment Expansion 1.3, and Learnable Innate Skills 1.0 evidence. Definitions use `base:` or `mod:<project>:` identities directly in catalog construction, artwork bindings, and source receipts. Numeric model families remain distinct, and mode variants keep separate IDs. Provenance belongs in source metadata. Development catalog revisions and source-prefixed entity links are not shipped. Imported catalogs and saved user revisions retain exact identities and checksum pins.

Native databases and reviewed game code supply gameplay facts, generated effect descriptions, world placements, acquisition routes, and class artwork. The wiki retains useful directions, strategy, historical claims, and artwork without a verified native equivalent. Reviewed links connect duplicate entries to native identities using matching fields and relationships, never names alone. Remaining community content is classified for further source review; retention does not establish that native evidence is unavailable. See [native reference projections](native-reference-facts.md) for replacement coverage and retained boundaries.

Bundled projects are listed in [`bundled-mod-sources.json`](../src/catalog/bundled-mod-sources.json); digest-named compressed wrappers in `src/assets/mod-sources/` preserve their full native project JSON. Every project uses the shared importer. [`mod-defaults.json`](../src/catalog/mod-defaults.json) records the optional starter selection and historical aliases. The generated compact index supports discovery; full original sources are loaded before definitions are saved or enabled. See [the mod data pipeline](crystal-edit.md#bundled-mod-evidence).

The earlier Moonlight projection, identity links and mixed `catalog-v1` definitions remain compatibility evidence for saved records. [`legacy-catalog-v1.json`](../src/catalog/legacy-catalog-v1.json) freezes the original catalog and source identity mapping. The immutable `catalog-v2` snapshot preserves the preceding base revision. Fresh profiles use `catalog-v3`, assembled directly from the fingerprinted native databases and explicitly retained reference supplements. Its construction does not read the historical archives or the per-mod projections; changing the default does not rewrite old pins.

An explicit source null is known absence, displayed as **Not set in source**. It does not establish the runtime result of an optional override. Zero resource costs, false flags, empty modifier lists, authored descriptions, class equipment permissions, and PP costs are retained from the records. Planning details show supplied fields that apply to the definition kind. They do not add PP or equipment-slot uncertainty to an ability. Personal inventory, learning, progress, and enabled-mod choices retain their own knowledge states.

The [certainty audit](catalog-certainty.json) distinguishes stored source gaps from the native presentation that replaces reviewed descriptions, acquisition notes, and duplicate entries. Geography and competing acquisition claims require separate evidence. Barbarian and Tempest observations lack corresponding ingested exports. Unimplemented calculations and unsupported modifier semantics retain their actual limits. The native and mod records do not establish every platform's version parity, authored strategy, artwork binding, or content license.

Generate a new portable mod snapshot with an owned Crystal Edit export:

```sh
npm run mods:bundle -- --input <mod-export.json> --output src/catalog/<new-snapshot>.json --key <project-key> --mod <recorded-mod-name>
npm run mods:bundle -- --check --output src/catalog/<new-snapshot>.json
npm run certainty:audit
npm run certainty:check
```

The bundler preserves supported model records, version metadata, authorship, the source digest, and numeric identities. It excludes comments and private paths, never executes descriptions or formulas, and refuses to overwrite an existing snapshot. A new snapshot must be registered in a new catalog revision with reviewed identity links and its canonical checksum. Adding a file alone does not make it visible in the application. Offline checks require the committed snapshot rather than the original installation.

## Native gameplay facts are the base

The default catalog was extracted from the Windows 1.6.9.0 game installation. Its shared gameplay scope across the compared Windows and macOS builds is recorded in [verified platform coverage](platform-coverage.md); ordinary gameplay claims need only the game version, while extraction fingerprints retain their platform identity. The executable's PE version resource independently reports matching file, product, and assembly versions of 1.6.9.0. The bundled gameplay snapshot records that evidence, its executable hash, relative database names, database format versions, source hashes, and executable-derived enum labels. It contains enemies, enemy actions and nested conditions, drops and steals, abilities, status effects, equipment, items, classes and learn trees, passives, recipes, biomes, encounters, overworld enemy behavior, difficulty settings, growth records, and selected game configuration. Developer comments and unrelated system content are excluded.

Native definitions are ordinary catalog definitions available in Reference, inventory, learning, and planning. Empty authored descriptions can still have native effects: the interface renders supported modifiers, vocabulary, ability fields, and linked statuses from the pinned game records. Readable descriptions, including strategy and directions, remain visible under **Description** alongside native effects. The Sources popup retains attribution and corrected historical claims without repeating description text already on the page. Verified alternative entries appear under **Include other sources and mode variants** in pickers or **Additional reference > Other sources & mode variants** in Reference; names alone never hide an entry. Saved selections and direct links retain their exact identities, and commands link to their native class without becoming class records.

Verified native facts appear as ordinary content without citation markers. Small **Sources** markers stay attached to uncertain values and external claims, including wiki guidance and mod or imported records. Their popups retain attribution, applicability, and source disagreements. Native provenance remains in the immutable catalog, source manifests, and reviewed receipts; hiding routine citations does not discard evidence or broaden platform and version scope. The [game-code source audit](source-corroboration.md) records internal proof locators and checks every bundled revision without changing persisted catalogs.

Reviewed native equipment records display readable types from the game's equipment enum, such as **Light armor** for Dress. An equivalent inherited wiki **Type** does not repeat the native **Equipment Type** field. Exact catalog, record, and enum checks guard this replacement, while original labels remain preserved as source evidence. Changed or unsupported records keep their existing fields.

The maintainer's manual observations are scoped to Nintendo Switch 1.6.6. PC 1.6.9.0 and Switch 1.6.6 content equivalence is unresolved. Different version numbers do not establish missing Switch content or update lag. A team with a different recorded platform or version retains an unresolved parity check, with a direct action to review its pinned Game Setup. Game Setup retains its recorded platform and installed game version; an unspecified PC platform alone does not identify a fingerprinted build. The [verified Windows/macOS comparison](platform-coverage.md) establishes shared gameplay facts independently of the existing programmatic applicability checks. Wiki and guide material have their recorded, often unverified version scope; the older Crystal Edit class export does not become verified 1.6.9.0 evidence through this import.

The snapshot preserves the separate Vanilla and Chaos patch records. The inspected 1.6.9.0 loader applies them by native ID after loading the base databases. Patch definitions are labeled overrides, not inferred enabled modes. Raw enemy attributes and combat ratings are inputs, not a simulated battle sheet: automatic stat generation, difficulty, player-style enemies, modes, and mods can change effective values. Steal loot availability and per-attempt success stay separate. Repeated names, test enemies, and dummy records keep their distinct native IDs rather than being advertised as unique normally encountered enemies. Numeric enums provide labels, not automatic verification of every engine mechanic.

`src/catalog/native-game-data.json` is committed build-time input. The app bundles its normalized catalog for offline use and never reads a game installation or requests game data at runtime. Refresh it with Node.js 22.12 or later, a .NET runtime, and the ILSpy CLI:

```sh
dotnet tool install --tool-path <local-tool-directory> ilspycmd --version 11.1.0.9782
npm run game-data:update -- --input <game-content-directory> --decompiler <local-tool-directory>/ilspycmd
npm run game-data:check
npm run check
```

The updater decodes database containers and inspects executable metadata and enum declarations; it does not execute the game. Review source, identity, version, mode, and normalized changes before committing. Changed gameplay facts require a new bundled revision and its canonical checksum; never replace the content of an existing immutable revision. The offline check validates content digests, the generated catalog checksum, and exact bindings against the committed reviewed identity crosswalk. Fresh app checkouts require only the committed snapshot and ordinary Node dependencies; .NET, ILSpy, and an owned installation are needed only to refresh it. Native game data retains source-specific rights and receives no AGPL or wiki CC-BY-SA grant through this project.

Native enemy pages present identity, scoped version, HP/MP, level, rewards, combat inputs, attributes, drops, steals, and action references as compact bestiary entries. The Game mode dropdown offers Standard, Vanilla, and Chaos independently of Easy, Normal, and Hard difficulty. It opens the matching native enemy override by numeric ID, or retains the base record when that patch leaves the ID unchanged. Enemy rewards and actions come from the selected record, and action links use the selected mode's definitions with base inheritance. The Difficulty dropdown defaults to the source data's Normal difficulty and previews the inspected 1.6.9.0 rates for HP/MP, attributes, and attack/defense inputs, including boss rates and changed-vital rounding. Selection stays in the link's `mode` and `difficulty` query parameters and leaves saved Game Setups unchanged. Native difficulty IDs are Normal 0, Easy 1, and Hard 2; display order is Easy, Normal, Hard. Unknown selections remain unselected and show raw inputs. Changing a personal version to a different mode record opens that catalog entry without changing the saved personal version. Stat modifiers and battle effects can change final values. Loot availability and per-attempt steal success stay separate, and action weights are not displayed as probabilities. Technical details retains displayed engine fields and related definitions, with money shown as an integer in copper units. Complete native records and source fingerprints remain in the committed catalog and manifests; external claims and unresolved values retain their Sources popups. Missing exact artwork uses a neutral bestiary emblem. Money rewards and prices elsewhere use gold, silver, and copper denominations; source values and custom-definition editing inputs retain their copper units. Definition links retain browser tab behavior. Global search leads with base records, identifies same-name enemies by level, location, and record ID, and exposes other sources and mode variants through an explicit control. Filters stay on the Reference results page; issue reporting is available from the entry actions. Catalog records are read-only.

Monster and recipe links open exact definitions in the displayed catalog revision. Linked ingredients and required items open their own acquisition pages. Selecting Standard, Vanilla, or Chaos applies numeric-ID overrides with base inheritance before resolving monster loot and recipe outputs. The mode stays in the Reference URL through reloads and acquisition links, including opening links in another tab. Drop chance, steal availability, and per-attempt steal success remain distinct recorded values rather than an effective farming calculation.

Its immutable source digest pins the executable, editor, world, biomes, system data, and native catalog content. World routes appear only for a matching catalog source. This reference projection does not alter persisted catalogs, personal versions, inventory, or progress. Shop costs use the inspected integer rate and rounding rules. The projection preserves page priority and nested branch conditions, sequential trade inputs, source coordinates, and proof locators while excluding dialogue and raw scripts. Known requirements render as player-facing text and definition links; unsupported story or interaction conditions remain explicit. Recovery stock is labeled separately from ordinary acquisition. Randomizer mappings and mod changes are not established by the base-world projection.

Reviewed world conditions explain Salmon Run placement, returned penguins, Sky Arena victories, and unclaimed prizes using their native counters and flags. [Condition facts](../src/catalog/acquisition-condition-facts.json) bind each explanation to an exact world digest, entity, condition, and proof locator. Changed conditions and unrelated entities keep the unresolved explanation rather than inheriting a meaning from a similar variable name.

The Shady Merchant's Rotten Salmon trade includes its native dialogue choice fee. [Route facts](../src/catalog/acquisition-route-facts.json) connect the exact Buy choice, charged currency, answer variable, and reward branch to the fingerprinted world and game code. The price projection requires the reviewed Standard-mode route and preserves the immutable world snapshot; unrelated choices and modes receive no inferred fee.

Native routes replace complete reviewed acquisition claims in ordinary Definition facts. [Acquisition receipts](../src/catalog/acquisition-guidance-receipts.json) preserve the original field value and require its complete native replacement to match. Readable acquisition descriptions remain on the page even when a native route confirms them. The **Sources** popup retains the field attribution and replacement evidence, along with historical claims not already displayed. Description wording can be enhanced independently of the immutable source records. A native steal route does not corroborate a wiki drop claim. These read-only projections preserve catalog checksums, historical revisions, and saved references.

Seed pages show native growth time, the exact whole-minute reduction from watering once, and links to the harvested encounter. [Gardening facts](../src/catalog/native-gardening.json) pin the inspected executable, native catalog, and quest code that maps seeds to encounter IDs and growth times. Watering subtracts half the original growth duration rounded down to whole minutes from the sprout deadline; it does not apply a continuously doubled growth rate. The gardening view requires the reviewed catalog and exact seed and encounter records. It does not infer planted seeds, elapsed time, harvest readiness, or inventory.


The updater verifies reviewed source fingerprints before running the game decoder on a temporary assembly copy, checks every entity ID and coordinate against the embedded world ledger, then emits only normalized acquisition facts. Installed files remain unchanged. Offline integrity checks require only the committed projection and Node dependencies; they run in `npm run check`. Source-specific game rights apply to these facts. Synthetic fixtures exercise extraction and scope boundaries without including proprietary world exports.

**No acquisition route found** means no route was resolved from the indexed sources, not that the item is unobtainable. A database definition, recipe, or conditional grant does not independently prove a reachable gameplay path. Guidance without a complete native replacement remains visible under Description, Guide notes, or its original field, with attribution available through **Sources**. Native routes and gardening facts need no routine citation marker. Unmapped imports, unsupported conditions, test records, mod sources, and platform parity retain their actual limits.

## Native world map

**World Map** renders a fully revealed bundled atlas and normalized placement data from the inspected 1.6.9.0 game data. [The map manifest](../src/catalog/world-map.json) pins the source fingerprints, map geometry, layer assignments, projection coordinates, and emitted asset hashes. The extractor composes the native map cells from `Content/Worlds/field.dat` using the inspected voxel texture atlas, point sampling, height shading, and underwater shading. Native biome metadata supplies labels and overworld, cave, and dungeon assignments. Layer PNGs ship locally in `src/assets/world-map/` and are included in offline preparation. The application does not read a user's installation or retrieve game data at runtime.

Markers resolve native entity IDs, coordinates, biome identities, chest contents, NPC interactions, encounters, and landmarks through the retained native records. Conditions describe source interactions rather than inferred Playthrough state. Ordinary NPC markers require a recorded appearance; invisible script triggers are omitted, while supported shop and battle interactions retain their markers. Unresolved boss and interaction details remain explicit. The view never records ownership, chest completion, NPC availability, or defeated encounters.

Resource and object markers remain separate from people even when the native entity format uses an NPC interaction record. Mining nodes require the recorded mining action and item rewards; planting plots use the garden action, and ground pickups require the authored sparkle or question appearance and an inventory reward. Voxel-backed props use the exact voxel definition label and belong to Objects. Effect-only props without loot also remain Objects. Boss and shop interactions retain precedence. Creature and human actor placements remain NPCs. This classification uses source interactions and appearance fields rather than inferring a person's identity from an internal key.

Mod previews consume exact bundled sources or retained imported Crystal Edit source revisions, using the same ordered Game Setup pins as build planning. Native entity IDs identify base-world overrides; later selected layers take precedence without duplicating the overridden vanilla marker. New entity IDs stay scoped to their source project so independently added placements can coexist. Added and changed markers retain their source labels. Definitions resolve by numeric model family and ID, with explicit gaps when a referenced record is unavailable. Arbitrary projects are supported within the inspected export schema; a project title or similar name does not establish identity or compatibility.

Crystal Edit sources contain entity placements and model changes, but do not include replacement voxel world geometry. Previewing those sources leaves the native atlas as the backdrop, and does not prove the mod's terrain, runtime script behavior, or compatibility with another platform or game version. Unsupported entity types, coordinates, and conditions remain explicit instead of being guessed. Native map artwork remains copyrighted Crystal Project material; extraction fingerprints establish provenance and do not grant redistribution rights. Mod sources retain their own unresolved or recorded rights.

Refresh the map with an owned installation, Node dependencies installed from the lockfile, and .NET SDK 10:

```sh
npm run world-map:update -- --input <installation-or-Content>
npm run world-map:check
```

The update command verifies reviewed Windows executable, editor, world, database, and texture fingerprints before extracting map cells and decoding placement records from a temporary assembly copy. It emits normalized markers and rendered PNGs without retaining player saves, raw world archives, dialogue, scripts, or machine-local paths. Source-specific game artwork rights apply. The offline check needs only Node and the committed projection; it verifies the manifest digest, layer dimensions, PNG hashes, and asset membership without an installation. Review changed fingerprints and extraction scope before adopting another platform or version.

## Community wiki snapshot

The community reference snapshot is generated from the public [Crystal Project community wiki](https://crystal-project.fandom.com/wiki/Crystal_Project_Wiki) through its MediaWiki API. It includes class infoboxes and stat growth, class skill and passive tables, resource and learning costs, prerequisites, targeting and effect text, documented Vanilla-mode differences, equipment and item tables, item pages, monster templates, statuses, areas, commands, crafting recipes, and other substantive game-reference pages. Every extracted entity keeps its exact page revision, section or row locator, source applicability note, and page link.

The committed catalog contains normalized factual fields and plain text. Artwork is bundled separately as described below. The catalog does not retain advertisements, scripts, interactive maps, or executable wiki markup. Structured lists, records, and tables render as data in the reference view. The application never fetches the wiki at runtime.

The wiki identifies its content terms as [CC-BY-SA](https://www.fandom.com/licensing). Wiki-derived content remains under those terms and retains page-level attribution; the application's AGPL-3.0-only license does not replace source-content rights. Refreshing the snapshot requires reviewing both the generated changes and the upstream licensing declaration.

Currency amounts display as gold, silver, and copper coin icons, with the amount before each icon. `WindowHelper.DrawCurrency` in the fingerprinted Windows executable corroborates the conversion of 100 copper per silver and 100 silver per gold; its locator is recorded in the [code evidence](../src/catalog/game-code-evidence.json). Whole and mixed prices use descending nonzero denominations; zero remains zero copper. This applies to explicit currency amounts in costs, tables, descriptions, and read-only previews. Original source values remain intact in stored definitions, editing fields, and exports. Unknown or unsupported amounts stay as text, and metal item quantities such as Gold Ore are not treated as money. Coin images have accessible denomination labels and text fallbacks.

Community documentation can be incomplete, stale, internally inconsistent, or based on a different game release. The catalog therefore does not claim complete Nintendo Switch coverage, parity with a particular official mod-pack snapshot, or verified calculation order. Source disagreements remain conflicting claims. Missing kind-specific fields remain explicit unknowns.

The Quintar breeding guide retains the pinned wiki breeding entry's Method 2 as an ordered route and keeps useful capture landmarks. Pairing outcomes, minimum first-place finishes, readiness, food effects, nursery capacity, and Incubator consumption use fingerprinted 1.6.9.0 facts in [`quintar-native-evidence.json`](../src/catalog/quintar-native-evidence.json). The [native rules](../src/catalog/quintar-native-rules.ts) validate every route pairing. Race minimums depend on the partner's type: Desert and Highland require one distinct-track win, River two, Black three, Aqua four, and Gold five; Blue and Red impose no race minimum. The Ocarina price comes from native item and shop records. Keep/release advice is derived from each parent's last use in this route, not from observed nursery contents. Switch and mod applicability remain unverified. The guide does not calculate food quantities, recovery time, or total cost.

Reference details show every competing field value with its source, locator, revision, applicability, and any claim note. Different values can reflect wording or scope differences; the importer does not decide whether they describe the same fact. Conflicts remain unresolved in the source catalog. Use **Report a data issue** with the entry, game version, and evidence so fixes can be reviewed in the extraction or interpretation pipeline. Reference entries do not offer local field corrections or catalog cloning. Previously saved personal versions retain their exact fields and source history without replacing catalog claims.

### Native game artwork snapshot

Native items, equipment, classes, monsters, status effects, UI icons, and the Quintar guide use artwork extracted from a maintainer-owned Windows installation. This is a build-time snapshot only: the application never reads an installation, scans the machine, or requests game data at runtime. The extraction manifest records a content fingerprint over every inspected database pack, texture pack, and the game executable without retaining the machine-local input path.

The extractor strictly reads the game's byte-inverted JSON databases and named PNG texture packs. The binary layouts are independently documented by the pinned [CrystalProjector database schema](https://github.com/iconmaster5326/CrystalProjector/blob/79320b343d603aa069aa023fd54020d36419e082/schema/ksy/database.ksy) and [texture-pack schema](https://github.com/iconmaster5326/CrystalProjector/blob/79320b343d603aa069aa023fd54020d36419e082/schema/ksy/texture_pack.ksy). Indexed icons use the exact 32x32 cell rule verified against the fingerprinted Windows executable. Class artwork combines both explicitly recorded actor-sheet variants using the executable's class-icon crop. Catalog bindings do not identify sprites from filenames, visual resemblance, or display-name similarity.

Native catalog definitions use their own database ID and mode scope to bind artwork from the exact retained source record. The updater requires the inspected executable and gameplay database fingerprints to match `src/catalog/native-game-data.json`; the artwork manifest also pins that snapshot's bytes and version. Base records and Vanilla or Chaos overrides receive separate bindings, even when their artwork is identical. Monster artwork uses the complete named texture from each record, preserving distinctions between same-name enemies. Null texture references do not inherit artwork from another mode, an alternate texture, or a similar label.

`src/catalog/game-identities.json` is the explicit bridge from bundled catalog IDs to native database IDs. It is generated from a full pinned commit of the public Crystal Project Archipelago item table and its constants, whose numeric codes document the native database ID plus a category-specific offset. The generator accepts only an exact supported source namespace and one upstream record. Display-label differences between that source and the installed database are preserved in coverage metadata; the numeric crosswalk, not punctuation or spelling, establishes the record identity. Catalog entries from other sources remain explicit identity gaps.

`src/catalog/game-assets.json` inventories every named embedded texture, every inspected data file, all database references to those textures, input hashes, extraction regions, catalog, guide, and UI bindings, and unresolved artwork cases. `src/catalog/game-artwork.json` is the smaller runtime projection. Content-addressed PNGs in `src/assets/game-assets/` contain only the exact images needed by catalog, guide, and UI bindings. An ability record with no direct texture path stays unresolved rather than inheriting a guessed generic icon. Source-label discrepancies and records without direct artwork stay reviewable in manifest coverage.

UI sprites use explicit `uiArtwork` bindings in the [extraction manifest](../src/catalog/game-assets.json) and [runtime manifest](../src/catalog/game-artwork.json), which retain source texture hashes and regions. Offline checking rejects missing bindings or changed extraction regions and source identities. These UI sprites use the same content-addressed asset directory and refresh command as catalog artwork.

The Quintar guide's native artwork is pinned in the same manifests under `quintarGuide`. The Babel Quintar and Quintar Ocarina tiles use indexed icon cells checked against their installed item database records. Wild capture tiles use texture paths checked against the installed monster database, and the game system's type labels resolve Teal to River and Yellow to Desert. Breeding tiles use a named Quintar egg texture because the game files do not identify a distinct image for each bred result. The Golden tile uses a bounded frame from the named Golden Quintar actor sheet. Images illustrate guide steps and do not represent observed nursery contents. Capture variants link to native monster IDs with their type retained in the link label. Hatch steps link to the Incubator item; the wild Quintar Egg monster is not a nursery egg definition. The bundled Reference has no separate entries for individual bred variants.

The Travel & unlocks checklist includes item identities absent from the public crosswalk. `src/catalog/game-travel-identities.json` records reviewed item database IDs and the exact `item.dat` checksum inspected for them. The asset updater checks each record's ID and label against that database before extracting its icon; a changed database requires review of these bindings. Native record IDs, texture crops, and database fingerprints remain in the committed extraction manifests; ordinary Reference details omit this proof of provenance.
