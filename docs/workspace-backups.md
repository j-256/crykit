# Complete private workspace backups

A `.crykit` download is a complete saved workspace snapshot. It includes planner data and original source bytes, exact catalogs, selections and local bookkeeping, Editor originals and saved unfinished text, Save original and working bytes with saved pending fields, assets, library defaults, retained file history, pending content, and all conflict branches. Unknown typed values and source provenance remain unchanged. Imported descriptions, formulas, and file contents remain inert.

The downloaded file is unencrypted and can contain private notes, unfinished input, deleted-file history, and original imports. Store it privately. Export waits for the planner queue and asks the active form owner to save. A failed save or unresolved form stops export. A file save that replaces the opened workspace requires another explicit export from that new workspace. Crash recovery exports only the last durable complete workspace; unsaved fields lost with the failed view are unavailable.

The complete reader returns a validated inert snapshot. It does not install records, replay pending commands, activate an account, or grant source revision authority in another workspace. Destination selection, confirmation, and transactional installation belong to the separate restore flow. Native planner ZIP 2.0.0 and 2.1.0 imports and their resource limits remain supported independently. Native ZIP exports keep their declared planner-only scope.

## Capture and lifetime

`captureWorkspaceSnapshot(repository)` uses the exact repository that was opened. Account capture binds the committed head and entry identities, archives original current-unit closures, and retains complete materialized catalogs alongside original packaged-pin evidence. A strict versioned `sourceEvidence` annex associates each original unit with its current projected logical record. It does not fabricate pending content or file history. Local Playthrough revision and update counters remain exact even when their semantic owner frame did not change.

Fresh accounts store the current bundled game catalog. Managed planner saves add an exact older bundled revision when a new reference needs it, including a copied historical Build. Opened and restored workspaces retain every captured catalog revision and historical original.

Guest capture freezes the selected planner, file, and untouched legacy Inspector stores under the existing overlapping readonly capture protocol. Its final comparison checks exact captured records and bytes, including writes that leave the workspace manifest unchanged. Legacy inline and chunked Inspector text is translated without schema upgrades, cache writes, or applying draft text. Original byte identity is explicitly `text-only`; exact UTF-16 code units, including lone surrogates, are preserved. Unknown layouts or metadata fail visibly. A legacy inline row must still fit the browser's native record read; the streaming format cannot remove that storage API limitation.

Snapshot metadata is cloned and frozen separately from repository objects. Lazy blob capabilities retain their own lifetime. Export rechecks the selected source, profile generation, and committed capture before writing the final manifest. A changed source leaves an incomplete archive and reports failure; a hash is an integrity check, not authority.

Guest backup and explicit local-copy captures retain every stored catalog. They add app-bundled revisions only when those revision IDs appear in captured metadata, including historical and inert fields. This conservative selection avoids copying unused app data into private originals; semantic validation still determines which references can use a catalog. Native staging comparisons keep their complete app view, and existing stored snapshots retain their exact metadata and bodies.

Every `readWorkspaceBackup(stream, { signal? })` invocation creates a fresh nonextractable operation key and encrypts binary staging chunks with AES-GCM before writing IndexedDB, including guest reads. The key remains in memory and is independent of account keys. Returned blob readers reopen the encrypted staging without consulting an ambient profile. The public snapshot fields contain portable metadata and lazy content, while cleanup ownership stays in a private WeakMap.

Consumers must call `await disposeWorkspaceSnapshot(snapshot)` in `finally`, or explicitly transfer that obligation to another owner. Reader validation failure and cancellation await the same idempotent deletion promise. Explicit disposal revokes readers immediately and awaits deletion. Browser termination can prevent deletion and leave encrypted staging databases; their memory-only keys are lost, so those bytes cannot be recovered. Browser storage quotas and storage failures remain visible failures, not permission to omit content.

## Framing and validation

The file begins with ASCII `CRYKIT-WORKSPACE/1\n`. Each frame contains a little-endian unsigned 32-bit metadata length, strict UTF-8 JSON metadata, a little-endian unsigned 32-bit payload length, and payload bytes. Frame metadata is bounded to 64 KiB and each payload to 4 MiB. The container permits at most 1,000,000 frames and 32 GiB of input; metadata nesting is bounded to depth 64. These are container limits, not changes to existing per-file acceptance limits.

Content frames declare `kind`, document ordinal, key, encoding, schema version, chunk ordinal, final-chunk flag, payload length, and SHA-256 digest. Document zero carries snapshot metadata using the internal `deflate-json-tokens-v1` codec. Remaining documents carry exact independently reopenable bytes in the declared blob-registry order. The metadata references the original encoding (`bytes`, UTF-8, or UTF-16LE) and complete length and digest for each blob.

Each compressed metadata payload starts with a little-endian unsigned 32-bit expanded length, followed by one canonical raw-DEFLATE token page. Both compressed payload and expanded page are bounded to 4 MiB. The pinned fflate v0.8.3 level-6 encoder defines the canonical bytes for this codec version. The reader feeds small bounded compressed slices to its streaming inflater, rejects expanded overflow before consuming later input, requires the exact expanded length, and re-encodes that bounded page to reject trailing or noncanonical compressed bytes. A dependency upgrade must preserve this v1 behavior or retain a versioned decoder; accepting arbitrary equivalent DEFLATE streams would change the compatibility contract. Outer payload digests cover the exact compressed bytes.

Each expanded token page is a JSON array. Containers use `["object"]`, `["array"]`, and `["end"]`; fields use `["key", string]`; scalars use `["value", null|boolean|finite-number]`. Strings use `["text-value", string]` or `["string"]`, one or more `["text", string]` fragments, and `["string-end"]`. JSON escapes preserve exact UTF-16 code units. The encoder emits bounded pages without stringifying the whole workspace. The reader validates token arity and ordering, rejects duplicate and prototype keys, nonfinite values, incomplete containers and strings, extra roots, and excessive depth. Its node budget derives from the container byte limit rather than adding a content cap. The typed metadata tree still requires memory proportional to typed metadata; binary content is staged incrementally.

The terminal frame declares `format: "crykit-workspace-backup"`, `version: "1.0.0"`, preceding frame and byte counts, document count, revision-vector digest, and accumulated unkeyed SHA-256 chain. The chain starts as 64 ASCII zeroes; each content step hashes the prior lowercase hexadecimal chain followed by the exact framed metadata and payload, including their little-endian lengths. Vector hashing uses JSON-encoded key/value pairs sorted by key. A terminal frame has an empty payload. Complete EOF, frame order, counts, lengths, digests, strict state allowlists, and all required current, history, pending, conflict, and original-unit edges must validate before the reader returns. Duplicate, missing, foreign, orphaned, truncated, and trailing content fails closed.

## Downloads and resource behavior

When available, the file picker starts during the explicit user action, before capture awaits. Writes honor sink backpressure. Failure aborts the sink and retains the source workspace. Unsupported browsers use a bounded 128 MiB Blob fallback that fails visibly on overflow without trimming history or files. Profile changes abort the operation, and account object URLs participate in profile cleanup. A requested browser download is not proof that the user retained a filesystem copy.

Synthetic coverage includes a streamed binary body larger than the fallback bound, exact repeated reads, invalid UTF-16 draft preservation, produced Editor and Save history, conflict alternatives, source-evidence corruption, final same-manifest guest changes, native nonempty-source ZIP compatibility, and encrypted-staging cancellation. Metadata compression keeps repeated catalog structure compact without dropping source evidence or changing the fallback bound. Fake IndexedDB retains encrypted records in the test process, so its process memory measurements are not evidence of browser disk-backed peak heap usage.

## Guest inherited originals

Named guest files databases use layout v2. The mandatory `workspaceExtensions` document points to strict inherited-snapshot and planner-evidence graphs, including an explicit empty graph. A supported v1 database upgrades its validated rows and empty extension in one native transaction. Missing v2 evidence is corruption, never an empty legacy workspace. A blocked upgrade requires the other tab to close; older complete readers reject the extension instead of silently dropping originals. Planner-only save and undo preserve these stores.

Historical originals retain exact backup token pages and their ordered full native references in separate evidence stores. Pages preserve token boundaries; native bytes use bounded chunks. The membership digest covers sorted original IDs with a versioned domain prefix, while exact stream, body, subset and reachable-row validation establishes integrity. Imported saved changes and journals remain inert evidence. Saved changes retain the frozen backup entry validation and uniqueness rules without borrowing the operative local change list limit. They do not replace operative planner history or grant undo authority.

An inert guest evidence import copies the destination planner, Inspector and current files into fresh containers, validates their exact copied rows through independent handles, checks the complete staged planner/evidence composition for saved-change collisions, and changes the inherited sidecar through the existing guest coordinator. Ordinary full commands carry the captured sidecar; recovery commands carry the selected frozen recovery capture's sidecar. Neither path adds the intervening current projection to inherited history. Owned-file success receipts compare the complete sidecar as well as the file result.

`joinWorkspaceSnapshotEvidence(current, inherited, options)` combines an owned current v1 projection with an exact inherited set and returns a registered v2 snapshot. Success transfers the current owner's lifetime to the result, and failure leaves it owned by the caller. Disposing either adopted owner invalidates the result. Historical metadata is validated from its stored token stream, while current metadata comes from the already validated immutable current projection in its original property order. Archive reading still validates stored framed bytes through terminal and EOF before construction. Export retains the same frozen guest comparison until its terminal frame; it never substitutes mutable live rows for captured bodies.
