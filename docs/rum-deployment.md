# Cloudflare performance monitoring

Cloudflare Web Analytics, also called real user monitoring (RUM), is planned for CryKit to diagnose performance and stability problems. Keep [single-page application measurement](https://developers.cloudflare.com/web-analytics/get-started/web-analytics-spa/) enabled so navigation within the app produces performance measurements. Adapt the app's rendered metadata to the collection boundary below. The [privacy terms](accounts-privacy.md#website-performance-measurements) describe browser measurements and provider-managed records. RUM activation is separate from account activation, application diagnostics and producer logging.

## Manual embedding and activation scope

On 2026-11-10, Cloudflare Fleet readback confirmed enabled Configuration Rules `crykit_disable_rum` for `crykit.lasers.app` and `crykit_preview_disable_rum` for `preview.crykit.lasers.app`, both setting `disable_rum: true`. Keep those rules enabled to suppress automatic injection. CryKit uses manual embedding with a separate collector origin; disabling the rules would reintroduce the same-origin collection path or a duplicate beacon.

Use Fleet to verify the exact host's automatic-injection block and preserve unrelated host rules. Inspect the Web Analytics site's host and regional settings as well; a source change does not establish which visitors appear in reports. Do not assume regional exclusions implemented through automatic injection also apply to a manual snippet. Configuration Rules take precedence over [Web Analytics rules](https://developers.cloudflare.com/web-analytics/configuration-options/rules/). Customer-account gates remain separate.

Set `CRYKIT_RUM_SITE_TOKEN` to the public site token from the matching Cloudflare Web Analytics snippet when building an enabled release. It is a public reporting identifier, not an API credential. The build emits the documented manual script with `spa: true` and lets it use Cloudflare's separate collector. Missing or empty configuration emits no script; invalid configuration fails the build. Ordinary local builds and forks therefore do not report to the maintainer's analytics site.

Production CI reads the GitHub repository variable `CRYKIT_RUM_SITE_TOKEN` only for the canonical repository's main-branch release build. PR verification builds omit it. After local verification and rollout review, configure the variable, publish the release and complete the live checks below; activation is not qualified until those checks pass. Preview builds receive their intended site token through the same environment variable before `npm run build:preview`. Both public HTML and the offline cache digest are produced from the selected configuration. To roll back collection, clear the build setting and redeploy; keep the automatic-injection blocks enabled.

## Collection boundaries

Cloudflare documents page and referrer information, performance timings and [report dimensions](https://developers.cloudflare.com/web-analytics/data-metrics/dimensions/). Its [FAQ](https://developers.cloudflare.com/web-analytics/faq/) says query strings are not logged, but that statement alone does not establish what every outbound field contains. The beacon is third-party code running in the page; not reading browser storage does not prevent it from observing rendered elements or resource URLs.

A synthetic, intercepted Chromium check on 2026-11-10 found that the downloaded beacon stripped query strings and fragments from top-level page/referrer fields, but sent DOM identifiers in interaction attribution and unsanitized image URLs in rendering attribution. A fixture matching a scenario card exposed a marker representing a private record from its ancestor element ID. Disabling SPA measurement did not remove those fields. These observations apply to the tested artifact and cases; they do not establish a permanent provider contract or complete browser coverage.

Scenario navigation therefore uses element references held in memory instead of putting persisted record IDs in HTML IDs. Keep private record IDs, names and imported content out of DOM IDs and classes: RUM's interaction and layout attribution can include an element's ancestors. Ordinary static presentation classes and transient accessibility IDs remain useful for diagnostics. Internal React keys and persisted formats do not need to change.

Private artwork and screenshot previews use browser-created blob URLs. Those URLs identify an ephemeral resource; they do not contain the image bytes or original filename. Preserve that distinction when reviewing payloads. Do not replace them with data URLs or remote URLs containing private names, query parameters, fragments or access tokens: rendering attribution can copy the resource URL without the sanitization applied to page URLs. A blob handle appearing in a measurement is not a disclosure of its image contents.

The same-origin collector used by automatic injection receives CryKit's account cookie through ordinary browser request handling, even though the beacon does not read that cookie in JavaScript. An intercepted signed-in check demonstrated this on 2026-11-10. CryKit therefore uses the [documented manual collector](https://developers.cloudflare.com/web-analytics/faq/) at `https://cloudflareinsights.com/cdn-cgi/rum`, which is outside the account cookie's host scope. Do not change the account cookie's security attributes to accommodate analytics.

Both the public HTML meta policy and `public/_headers` permit the exact `https://static.cloudflareinsights.com/beacon.min.js` script and the separate collector URL, retaining all unrelated restrictions. Keep both policies aligned. The administrator entry points retain their stricter meta policies and receive no manual snippet. `Referrer-Policy: no-referrer` and the matching meta policy prevent query-bearing document URLs from appearing in HTTP Referer headers.

Before enablement:

- Prevent private record identifiers, imported content, passwords, keys, active session cookies, verification capabilities and portable-share payloads from reaching beacon bodies or request headers. Check page/referrer fields, image URLs and element attribution independently; changing only page URL handling is insufficient.
- Capture synthetic measurements for initial navigation, hash routes, history navigation, interactions and page exit. Include guest/account views, sharing, verification and administration. Require positive evidence that SPA navigation and useful performance attribution still work; an empty capture is a failure. Preserve the administrator entry points' existing script restrictions.
- Preserve the existing `Referrer-Policy: no-referrer` protection and permit only the exact required beacon script and collector in CSP. Do not widen script or connection policy to arbitrary external origins. Verify the effective headers on each selected page.
- Publish matching privacy copy, inspect actual injection and payloads, and verify that blocked or unavailable analytics do not break guest editing, account workflows or offline use. Verify collector acceptance as well as browser emission: Cloudflare's [FAQ](https://developers.cloudflare.com/web-analytics/faq/#errors) describes a Referer/Origin requirement, so an intercepted local success response does not establish that the live collector accepts requests under `no-referrer`. Retain that protection while resolving any ingestion failure. Keep producer logs, traces and private Tail forwarding under their existing restrictions.
- Record the exact host, serving artifact, beacon artifact, regional scope, payload evidence and reversible provider change. Recheck after relevant application or beacon changes. Remove the manual snippet through the build setting and restore the restrictive script policy if the verified collection boundary fails. The automatic-injection blocks alone do not stop a manually embedded beacon.

## Local browser verification

Use a fresh synthetic browser context and the actual built application. `npm run verify:rum -- --beacon /path/to/beacon.min.js` requires an explicitly supplied, digest-checked Cloudflare artifact. The command does not download vendor code or send analytics to Cloudflare. Keep the external artifact outside the repository; review changes to its pinned digest together with collection behavior.

Prepare the inputs with `npm ci`, `CRYKIT_RUM_SITE_TOKEN=11111111111111111111111111111111 npm run build:assets`, `npm run build:account-tests` and `npx vite build --config vite.accounts.config.ts`. The repeated-ones token is a synthetic fixture identifier. Use this artifact only in the intercepted proof; rebuild without the setting before serving a normal local review. Install Playwright Chromium with `npx playwright install chromium` when needed. The proof also requires OpenSSL for the local account fixture. Run the proof after building and keep its inputs unchanged for the duration.

The proof intercepts the beacon and separate collector, retains the built CSP and referrer policies, and blocks unknown browser destinations. Its local account service captures email and rejects outbound delivery. It checks synthetic private markers and active account-cookie values in request bodies and headers as well as rendered attribution fields. Expected-failure controls preserve the historical DOM-ID and same-origin cookie exposures so those boundaries cannot silently disappear from coverage. Receipts go to `test-results/rum-proof` by default; use `--output` to retain them elsewhere. Missing or changed vendor bytes, missing build inputs and missing measurements fail verification. This explicit external-artifact check supplements the regular source and browser suites; it does not silently skip inside the ordinary verification gate.

Local proof does not establish the deployed manual snippet, regional coverage, real Cloudflare retention, every browser engine or future beacon behavior. Verify those deployment-specific boundaries separately. Cloudflare does not support stable version pinning for the manual script, so the pinned test artifact does not pin the script that visitors receive; see its [SRI guidance](https://developers.cloudflare.com/web-analytics/faq/#how-can-i-enforce-subresource-integrity-sri-with-the-js-beacon). Retain strict referrer protection even when JSON page fields are sanitized, because request headers are an independent channel.

## Provider limits and retention

Web Analytics is available without a paid plan, but its own host/path [rules](https://developers.cloudflare.com/web-analytics/limits/) have no Free allowance. Configuration Rules are a separate product with separate quotas. Verify the chosen exclusion mechanism against the zone's actual entitlement; do not assume Workers Paid supplies it. These product distinctions were checked against the linked documentation on 2026-11-10.

Cloudflare's [FAQ](https://developers.cloudflare.com/web-analytics/faq/#is-the-data-sampled) describes unsampled measurements for seven days, sampled longer-term data and reports for the previous six months. The application's seven-day log, 30-day summary and 90-day audit policies do not control Cloudflare's RUM dataset. Report availability is not proof that every provider copy has been deleted. Retain the provider's stated limits in the privacy disclosure without claiming a stronger deletion guarantee.
